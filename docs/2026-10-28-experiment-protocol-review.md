# Zero-shot VLN-CE 实验设计：核查与修订建议

日期：2026-10-28（Asia/Shanghai）。
待核查的共享建议：https://chatgpt.com/s/t_6ae15c85a38c8191ac451538ef1a543c
状态：研究设计修订，尚未实施新实验臂、调用模型或变更既定工程协议。

## 一、保留的研究问题与定义
研究冻结决策模型是否能依据第一人称观测与指令完成完整VLN-CE闭环；
比较图像直接决策与文本化视觉描述的差异，并分别测量动作表示、几何、记忆的贡献。
不把局部动作分类、脚本回放或特权oracle成功当作模型导航证据。
“决策模型未进行VLN微调”和“系统没有导航监督训练组件”分别披露；不声称基础模型预训练未见过导航数据。

## 二、必须修正的评测口径
本项目所固定的Habitat Success实现要求显式STOP，且目标测地距离严格小于配置阈值；
在3m阈值下为 STOP且NE<3，而不是仅NE<=3。OS表示曾到达成功半径内，不要求STOP。
SPL的初始距离采用实际reset后的测地距离，路径长度从实际位置计算，不以稀疏参考线长度替代。
SDTW在相同评测口径下为success乘nDTW；当前项目尚未加入SDTW字段，不能在表中伪称已报告。
缺dense GT时nDTW/SDTW应报告不可用及覆盖率，不能用reference_path静默代替。
来源：[Habitat0.1.7 Success/SPL](https://github.com/facebookresearch/habitat-lab/blob/v0.1.7/habitat/tasks/nav/nav.py)、
[固定VLN-CE指标实现](https://github.com/jacobkrantz/VLN-CE/blob/729d141b2ee10628061ada74dd3a5b9f70faeba5/habitat_extensions/measures.py)。

当前运行是Habitat0.3.3工程移植。接口/数学规则核对与原始环境复现是不同验收；
正式跨论文比较仍需核对navmesh、滑动、传感器、动作与数据版本。

## 三、实验拆成三个相互独立的比较
| 比较 | 只改变的因素 | 固定项及解释边界 |
|---|---|---|
| 输入模态 | Caption / RGB / 追加明确几何信息 | 同一原始传感器来源、动作候选、低层执行、安全层、历史与预算 |
| 动作表示 | 四动作 / 在线局部目标 / 像素区域候选 | 固定模型版本、输入来源和执行器；候选由在线观测产生 |
| 机制消融 | 基础 / +子目标记忆 / +不确定性策略 | 前两种比较冻结后，每次增加一个机制 |

不能把深度、相对位姿、航点、记忆与恢复全部同时打开，再将提升归因于“多模态”。
Caption组须计入视觉描述模型的耗时与费用；若使用不同决策模型，属于系统级比较，不能视为纯模态消融。
闭环方法走出不同轨迹后未来画面自然不同；固定的是初始状态、传感器和信息获取规则，而非强制每步画面相同。
如需同帧选择能力对照，另设离线标注帧诊断，不将其替代闭环结果。

现有StartLux适配器要求至少一张图；无图纯文本基线尚未实现。需先确认目标接口能力，
不能给黑图后仍声称该实验等同原生无图接口。Jev与StartLux的型号和版本分别记录，不沿用论文成绩。
不假设接口支持temperature或seed；只冻结实际支持的参数，报告服务端是否保证确定性。

每种动作表示均落到相同0.25m/15°底层执行。宏观选择次数、底层执行步数、HTTP尝试分开记录；
500步预算限制实际动作（含STOP），不可用“500个宏观航点”代替。每个底层动作保留碰撞、安全与轨迹记录。
仿真目标坐标、参考路径和最短路只供私有评测。当前策略输入仍不包含仿真真值位姿；
未来若增加里程计，应声明来源与误差，单独记录输入协议变化。

## 四、数据角色与规模
正式数据仍采用R2R_VLNCE_v1-3。小规模功能调试、提示与阈值选择先在train开发场景完成；
在本项目“val_unseen作为泛化留出”的约定下，不在同一批300个val_unseen上反复调参后宣称无偏评测。
若选择用val_unseen开发，应明确披露，并另设未触碰的评测集或官方test流程。
任务ID、scene、trajectory、repeat、配置与实际模型版本在运行前冻结。

共享建议中的50/300/1839只是候选规模，不是统计功效保证或新增调用授权。
先按独立批准预算做少量开发帧诊断和完整回合；依据失败类型与观测方差决定后续规模。
没有数据/预算时只执行软件对照，不能把完整运行等同于模型已理解图像。
现有三个公开测试场景都是已暴露开发夹具。未来扩展RxR-CE需单独定义语言、角色与数据版本。

## 五、停止与概率诊断
STOP Precision/Recall/F1必须先定义样本单位和正例：例如“在该次决策前的画面中是否具备停止条件”，
不能把动作执行后的距离标签错误配给执行前的预测。需要私有评测/人工标注对齐时间戳，且标签不进入策略。
动作分布的最大概率不是该回合成功概率或安全概率。Brier/ECE只针对事先定义的事件与对应标签计算；
例如显式的stop-ready二分类探针。连续导航可能有多个正确动作，不能把不等于参考动作直接判错。
相关概率校准研究：[Guo等，ICML2017](https://proceedings.mlr.press/v70/guo17a.html)。
在校准和受控验证前，不凭任意置信度阈值开启重观察或恢复；这些机制需要单独消融。

## 六、统计与效率
- 同episode、初始状态、配置及实际模型版本做配对，保留已开始回合的服务失败在分母中。
- 分别报告缺资源/初始化不可运行、已开始未完成、服务失败；不能仅报告完成任务的成功率。
- 同场景、同trajectory的多条指令与repeat不独立。报告场景/轨迹覆盖，并以场景/轨迹结构做聚类敏感性分析；
  未处理相关性的episode级McNemar或bootstrap不作为唯一显著性证据。场景数少时保守说明区间与功效限制。
  这是针对本任务相关样本的分析建议；聚类推断的一般依据见[Cameron与Miller](https://cameron.econ.ucdavis.edu/research/Cameron_Miller_JHR_2015_February.pdf)。
- 预先指定主要比较，再对扩展多重比较作适当校正；不挑最高一次运行或事后选择指标。
- 延迟分开记录输入构建、客户端HTTP往返、环境执行和episode墙钟时间；若无服务端计时，
  不能从HTTP往返时间单独识别“网络延迟”和“模型计算时间”。报告P50/P95、失败与重试。
- 公平预算需覆盖caption、规划、动作、进度、重观察、重试与异步轮询；分别报告HTTP数与实际可核对的费用，
  无供应商用量信息时费用标记不可用，不能以未知当0。
